# Research Brief

Use this reference for investigation that informs product, engineering, security, operations, or delivery decisions.

## Procedure

1. Restate the decision or question in one sentence.
2. Inspect available local context first: README, docs, package manifests, build scripts, configs, schemas, tests, and relevant source paths.
3. For current or external facts, use primary sources such as official docs, release notes, standards, vendor docs, source repos, or public APIs.
4. Record source freshness when recency matters.
5. Compare options against the user's constraints, not generic popularity.
6. State the recommended next step and what would invalidate it.

## Evidence Rules

- Cite local evidence with file paths and line numbers when available.
- Cite external evidence with source names and URLs.
- Mark unverifiable claims as assumptions.
- Treat third-party posts, benchmark blogs, generated docs, and forum comments as supporting evidence only.
- Do not copy large source passages.

## Artifact Integrity

- Working context belongs in the conversation or private notes, not in public docs, code comments, websites, API specs, database records, or PRDs.
- If a note explains how the research was conducted, keep it out of the artifact unless the audience needs audit detail.
- If the destination audience is unclear, ask whether it is internal or shared before writing.
